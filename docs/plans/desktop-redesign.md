# 桌面端重设计

## 为什么重做

旧桌面端的问题不只是"丑"，而是用不了：

- preload 引用了本地模块，在沙箱里加载失败，`window.zeroOneCli` 是 `undefined`，所有按钮静默无效。
- Agent 遇到写文件或执行命令就结束会话，界面没有任何批准入口。
- 没有流式输出，回答要等整轮结束。
- Agent 的工作目录是应用自己的安装目录，不是用户的项目。
- 设置没有界面，API Key 写进安装目录里的 `.env`。
- 左栏把会话、六个命令卡片、弹窗挤在 280px 里，主区域却几乎是空的。

后端已经修好（见提交 `2b6deaa` 之前的一组提交）。这份文档定义界面。

## 设计原则

1. **对话是主角。** 打开应用就能开始工作，其他功能是配角，不抢位置。
2. **每一次改动文件、执行命令之前，用户都看得到并能拒绝。** 批准不是弹窗打断，而是对话里的一张卡片，内容就是将要发生的事。
3. **状态永远可见。** 当前目录、模式、权限、是否在运行，不需要点开任何东西就能看到。
4. **没装好的地方直接说怎么办。** 没配模型、没选目录、没装 gh，都给出下一步按钮，不留空白。
5. **键盘优先。** 发送、停止、新会话、切换模式、批准，全部有快捷键，并写在界面上。
6. **浅色与深色一等公民。** 同一套令牌，只换取值；默认跟随系统。

## 视觉语言

参考 Anthropic 的气质，不使用其字体和标志：暖白底、衬线标题、陶土橙作强调、克制的阴影和圆角。

- 标题用衬线（思源宋体 / Noto Serif SC / Georgia），正文用无衬线，代码用等宽。
- 一个强调色（陶土橙），只用于主按钮、焦点和关键状态。其余全部是中性暖灰。
- 语义色（成功/警告/危险）只表达状态，并配文字或图标，不单靠颜色。
- 正文最大宽度 760px，行高 1.6，中文和英文混排不挤。
- 令牌集中在 `styles/tokens.css`，组件里不写死颜色。

```

│ 侧栏 272px    │  主区域                                         │
│              │                                               │
│ ＋ 新对话     │  [顶栏] 目录 · 模式 · 权限 · 停止                  │
│ 会话列表      │                                               │
│  · 今天       │  [对话流 760px 居中]                             │

│              │   助手消息（流式 Markdown）                       │

│ 启动台        │   文件改动卡片（diff）                            │
│ 工具          │   批准卡片（允许 / 本次会话允许 / 拒绝 / 反馈）      │
│ 设置          │                                               │
│              │  [输入框] 模式切换 · 发送                         │
└──────────────┴───────────────────────────────────────────────┘
```

侧栏底部三个入口：**启动台**（`hi path` / `hi run`）、**工具**（安装、技能、清理、API、支付）、**设置**。它们是主区域里的页面，不是弹窗，也不是塞在侧栏里的卡片。

## 关键流程

### 首次使用
1. 欢迎页：一句话说明 + 两步清单。
2. 步骤一「选择工作目录」：系统文件夹选择器，记住最近 8 个。
3. 步骤二「配置模型」：URL、API Key、模型 ID 三项，保存后立刻可用，Key 只显示掩码。
4. 两步完成后清单消失，进入空对话，给出 4 个可点击的起手提示。

### 一次对话
1. 输入，回车发送（Shift+回车换行，输入法组合中不发送）。
2. 助手文字逐字出现；推理内容默认折叠成一行「思考中…」。
3. 工具调用显示为一行：图标 · 名称 · 目标（路径或命令）· 状态。点开看结果摘要。
4. 写文件前出现批准卡片，内联显示 diff；命令前显示完整命令行，危险命令有醒目警告。
5. 批准选项：允许一次（Enter）· 本次会话都允许 · 拒绝（Esc）· 拒绝并说明。
6. 计划模式下，计划本身以文档形式展示，选项是「批准并开始实现」「继续修改」。
7. 随时可以停止；停止后对话保持有效，可以继续发送。

### 设置
分组：模型、AI 默认值、启动、GitHub、外观。每项即改即存；失败时就地显示原因并回滚。自动接受权限是危险项，需要二次确认并说明后果。

## 状态覆盖

每个界面都要有这五种：加载中、空、正常、出错、禁用。典型文案：

- 没配模型：「还没有配置模型。添加 URL 和 API Key 后就能开始对话。」[去配置]
- 没选目录：「先选一个项目目录，助手只会在这个目录里读写。」[选择目录]
- gh 未安装：「没有找到 GitHub CLI。」[如何安装]
- 配置文件损坏：说明路径并拒绝覆盖，提供「打开所在文件夹」。

## 无障碍

- 所有可交互元素可用键盘到达，焦点样式可见（2px 强调色描边）。
- 对话流是 `role="log"`，`aria-live="polite"`，流式更新不会打断读屏。
- 批准卡片出现时焦点移入，并在处理后回到输入框。
- 颜色对比度满足 WCAG AA；状态不只靠颜色。
- 尊重 `prefers-reduced-motion`。

## 快捷键

| 操作 | 快捷键 |
| --- | --- |
| 发送 | Enter |
| 换行 | Shift+Enter |
| 停止 | Esc（运行中） |
| 新对话 | Ctrl+N |
| 切换模式 | Shift+Tab |
| 允许一次 | Enter（批准卡片获得焦点时） |
| 拒绝 | Esc（批准卡片获得焦点时） |
| 打开设置 | Ctrl+, |
| 聚焦输入框 | Ctrl+L |

## 实现分层

- `state/transcript.ts`：对话状态的纯函数 reducer（已完成，有测试）。
- `state/store.ts`：多会话、设置、工作目录的应用状态。
- `ipc.ts`：`window.zeroOneCli` 的类型化封装。
- `components/`：只负责呈现，不直接碰 IPC。
- `pages/`：对话、启动台、工具、设置。
- `styles/`：令牌、基础、组件样式。

## 不做的事

- 不使用 Anthropic 的字体、Logo 和品牌素材。
- 不做云同步、账号、遥测、用量上报。
- 不在渲染进程里执行任何 shell、读写任何文件；一切经过白名单通道。
